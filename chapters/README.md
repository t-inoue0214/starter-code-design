# 章一覧（目次）

本編は全18章（第0〜17章）です。第0章で「プログラミングの考え方」の全体像と、この教材で使う3つの軸をつかみます。その後はすべて同じ題材（注文処理）を、パターンを変えて分解していきます。

各章は、用意された神クラス（1クラスに全部入った実装）を読むところから始まります。パターンの考え方を学んだら、自分の手でクラスに分解します。分解の前後で同じテストが green になることが、リファクタリング成功の目印です。

## 学ぶ順序の考え方

設計は、大きいものから小さいものへ決めていきます。まずアプリ全体の分け方、次に業務ロジックの置き場所、最後に個々のクラスの形です。この教材の章も、この順番で並べています。

- **Part 1 は基本の設計** です。Webサービスやバッチなど、業務アプリで広く使われる構成を学びます。最初に学んでください
- **Part 2 は条件が合えば使う設計** です。規模、変更の頻度、外部との接点などの条件が合ったときに選びます。発展的なアーキテクチャと、デザインパターンを含みます
- **Part 3 は選び方** です。条件から、どれを使うか、あるいは使わないかを判断します

デザインパターンは、アーキテクチャで決めた構造の中で、困りごとが出た箇所に足す部品です。継承による再利用は便利ですが、まず部品を持って委譲する形（コンポジション）を基本にします。

## コードのコメントの読み方

ソースコードは、初学者が1行ずつ読めるように、**ほぼ全ての行にコメント** を付けています。コメントは、何をしている行かを日本語で説明します。

その中で、**今回の分け方の要点** にあたる行のコメントだけは、先頭に「★重要★」を付けています。たとえば、依存の向き、責務の境界、処理を別のクラスに任せる箇所、部品を渡して組み立てる箇所です。解答例を読むときは、まず「★重要★」の付いた行をたどると、分け方の骨格がつかめます。

## 3つの軸

パターンは、何を決めるための考え方かで3つの軸に分かれます。番号は、設計を考える順番です。各章の冒頭に、その章がどの軸の話かを書いています。

| 軸 | 決めること | 該当する章 |
| :--- | :--- | :--- |
| ① アプリ全体の分け方 | 責務の区画と依存の向き | 第2章、第4〜7章、第10章、第11章 |
| ② 業務ロジックの置き方 | ロジックをどこに、どんな形で書くか | 第3章、第9章 |
| ③ クラスの作り方 | 部品の形と、その関係 | 第8章、第12〜16章 |
